# Requirements Document

## Introduction

Данный документ описывает требования к телеграм боту для поиска еды с использованием нейро-поиска по ресторанам и агрегаторам еды. Бот предоставляет пользователям возможность находить блюда по естественным запросам, используя интеллектуальную фильтрацию и геолокационные возможности.

## Requirements

### Requirement 1: Управление пользователями

**User Story:** Как пользователь, я хочу автоматически регистрироваться в системе при первом обращении к боту, чтобы начать пользоваться сервисом без дополнительных действий.

#### Acceptance Criteria

1. WHEN пользователь впервые отправляет сообщение боту THEN система SHALL автоматически создать профиль пользователя
2. WHEN система создает профиль пользователя THEN система SHALL запросить город для доставки
3. WHEN пользователь отправляет команду /address THEN система SHALL позволить изменить город для доставки
4. WHEN система создает профиль пользователя THEN система SHALL установить подписку "Базовая"
5. WHEN не "Базовая" подписка пользователя истекает через 3 дня THEN система SHALL отправить уведомление о необходимости продления

### Requirement 2: Нейро-поиск по запросу

**User Story:** Как пользователь, я хочу искать еду с помощью естественного языка, чтобы получать релевантные результаты без знания точных названий блюд.

#### Acceptance Criteria

1. WHEN пользователь отправляет текстовый запрос THEN система SHALL принять запрос длиной до 500 символов
2. WHEN система получает пользовательский запрос THEN система SHALL преобразовать его в структурированный JSON через Llama 3.1 8B из OpenRouter
3. WHEN система преобразует запрос THEN JSON SHALL содержать поля: тип блюда, кухня, ресторан, диета, ценовой диапазон, время доставки, исключения
4. WHEN система получает структурированный JSON THEN система SHALL отфильтровать список блюд из агрегаторов
5. WHEN система отфильтровала блюда THEN система SHALL дополнительно обработать результаты через LLM для повышения релевантности
6. WHEN пользователь отправляет запрос THEN система SHALL вернуть результаты в течение 5 секунд

### Requirement 3: Геофильтрация

**User Story:** Как пользователь, я хочу видеть только те блюда, которые могут быть доставлены в моем городе, чтобы не тратить время на недоступные варианты (изначально для выбора доступны только города Пермь, Воронеж, остальные города добавлю позже).

#### Acceptance Criteria

1. WHEN система получает город пользователя THEN система SHALL определить зону доставки
2. WHEN система выполняет поиск THEN система SHALL показывать только блюда из ресторанов с доставкой по городу пользователя
4. WHEN система проверяет доступность ресторана THEN система SHALL учитывать рабочие часы ресторана
5. WHEN ресторан имеет минимальную сумму заказа THEN система SHALL отображать блюда только если они соответствуют этому ограничению

### Requirement 4: Отображение результатов

**User Story:** Как пользователь, я хочу видеть подробную информацию о найденных блюдах в удобном формате, чтобы принять обоснованное решение о заказе.

#### Acceptance Criteria

1. WHEN система возвращает результаты THEN каждая карточка SHALL содержать фото, название блюда, название ресторана, описание, состав, цену
2. WHEN система отображает карточку блюда THEN система SHALL предоставить кнопку "Заказать" с прямой ссылкой на агрегатор
3. WHEN система возвращает результаты THEN система SHALL показать максимум 20 наиболее релевантных результатов
4. WHEN пользователь просматривает результаты THEN система SHALL предоставить кнопку "Показать еще" для дополнительных результатов
5. WHEN система не может загрузить фото блюда THEN система SHALL показать placeholder изображение

### Requirement 7: Сбор данных о меню

**User Story:** Как система, я должна регулярно обновлять данные о меню ресторанов, чтобы предоставлять пользователям актуальную информацию.

#### Acceptance Criteria

1. WHEN система запускается THEN система SHALL подключается к сбору данных
2. WHEN система собирает данные THEN система SHALL использовать веб-скрапинг для ресторанов без API
3. WHEN прошел 1 час с последнего обновления THEN система SHALL обновить данные меню для ресторанов
4. WHEN система получает новые данные THEN система SHALL кэшировать их для ускорения поиска
5. WHEN система не может получить данные от агрегатора THEN система SHALL записать ошибку в лог и продолжить работу с другими источниками

Для получения данных из Яндекс.Еда нужно использовать информацию в #Folder:/src/research/yandex eda/requests

### Requirement 8: Дополнительные функции

**User Story:** Как пользователь, я хочу иметь доступ к справочной информации и управлению сессией, чтобы эффективно пользоваться ботом.

#### Acceptance Criteria

1. WHEN пользователь отправляет команду /help THEN система SHALL показать список доступных команд и инструкции
2. WHEN пользователь отправляет команду /cancel THEN система SHALL отменить текущее действие и вернуться в главное меню
3. WHEN пользователь отправляет команду /start THEN система SHALL показать приветственное сообщение и основные возможности
4. WHEN пользователь выполняет поиск THEN система SHALL сохранить запрос и результаты в историю
5. WHEN пользователь отправляет команду /history THEN система SHALL показать последние 5 запросов пользователя

### Requirement 9: Производительность и надежность

**User Story:** Как пользователь, я хочу получать быстрые и стабильные ответы от бота, чтобы эффективно находить еду.

#### Acceptance Criteria

1. WHEN пользователь отправляет запрос THEN система SHALL ответить в течение 5 секунд
2. WHEN система обрабатывает до 100 одновременных пользователей THEN система SHALL поддерживать стабильную работу
3. WHEN происходит сбой в одном из компонентов THEN система SHALL автоматически восстановиться
4. WHEN система работает THEN доступность SHALL составлять не менее 99.5%
5. WHEN система обрабатывает запросы THEN использование RAM SHALL не превышать 4GB на экземпляр

### Requirement 10: Безопасность и соответствие

**User Story:** Как пользователь, я хочу быть уверен в безопасности своих данных при использовании бота.

#### Acceptance Criteria

1. WHEN система хранит API-ключи THEN они SHALL быть зашифрованы
2. WHEN система обрабатывает персональные данные THEN система SHALL соблюдать требования ФЗ-152
3. WHEN система сохраняет данные пользователя THEN система SHALL создавать резервные копии каждые 6 часов
4. WHEN происходит критическая ошибка THEN система SHALL уведомить администратора в Telegram
5. WHEN система обновляется THEN обновления SHALL устанавливаться без остановки сервиса

### Requirement 11: Мониторинг и логирование

**User Story:** Как администратор системы, я хочу отслеживать работу бота и быстро выявлять проблемы.

#### Acceptance Criteria

1. WHEN система обрабатывает запросы THEN система SHALL записывать детальные логи для отладки
2. WHEN система работает THEN мониторинг SHALL отслеживать время отклика, количество ошибок, статус сервисов
3. WHEN стоимость LLM-вызовов превышает 1800₽/месяц THEN система SHALL уведомить администратора
4. WHEN размер базы данных приближается к 90GB THEN система SHALL уведомить администратора
5. WHEN система выявляет аномальную активность THEN система SHALL записать предупреждение в лог
